# 单 Agent 还是多 Agent

**原则：能用单 Agent，就不用多 Agent。** 多 Agent 会增加调用次数、延迟和出错面。

引入多 Agent 之前，先逐条回答：

- [ ] 任务能拆成职责清晰、互不重叠的角色吗？
- [ ] 子任务需要不同的工具集、权限或上下文，单个 prompt 装不下吗？
- [ ] 需要并行来降低延迟吗？
- [ ] 角色之间传递的状态能用明确的 schema 定义，而不是靠聊天记录吗？
- [ ] 有评测数据证明多 Agent 在成功率、成本、延迟上优于单 Agent 吗？

**四种常见模式**

| 模式 | 做法 | 适合 | 注意 |
|---|---|---|---|
| Supervisor | 一个调度者分派任务、汇总结果 | 任务可拆分 | 调度者成为瓶颈 |
| Handoff | 按条件把控制权移交给下一个 Agent | 分流类流程（如客服） | 移交时的上下文要完整 |
| Debate | 多个视角互相质疑、交叉验证 | 需要审慎判断 | 成本高，需有终止条件 |
| Blackboard | 共享"黑板"，各 Agent 读写 | 松耦合协作 | 共享状态要严格管理 |
