# RAG 失败归因

**先分清是"没找到"，还是"找到了没用好"。** 答错时别急着调 prompt，沿链路逐层排查。

| 症状 | 先查什么 |
|---|---|
| 答案过时或缺失 | 数据源覆盖范围、更新时间 |
| 答案被截断、缺上下文 | 切分：块大小、重叠、是否按文档结构切 |
| 相关内容没被召回 | 查询改写、召回率@k、混合检索（关键词 + 向量）、embedding 是否适合该领域 |
| 对的片段排在后面 | 重排模型、Top-K 设置 |
| 找到了却答偏、编造 | 提示约束、强制引用来源、grounding 检查 |
| 多轮对话中答非所问 | 上下文压缩、查询重写 |

**方法：** 先建一个小型评测集（问题 + 应命中的文档），先测检索（召回率、命中率），再测生成质量。
